# 4.2 Datenvorverarbeitung

Die Vorverarbeitung wandelt die Rohdaten aus `ratings.csv` in einen Train/Test-Split um, der direkt von ALS (Kapitel 4.3) verwendet werden kann. Implementiert in `src/pipeline.py`.

## Pipeline-Übersicht

```
ratings.csv  →  einlesen  →  dropna  →  dropDuplicates  →  cast types  →  randomSplit 80/20  →  train, test
```

Die fünf Schritte sind als CLI-aufrufbare Pipeline implementiert und laufen unverändert sowohl lokal (Small-Datensatz) als auch auf der VM (25M-Datensatz).

## Schritt 1: Einlesen mit Schemaerkennung

```python
df_raw = (
    spark.read
        .option("header", True)
        .option("inferSchema", True)
        .csv(path)
)
```

- `header=True`: Erste Zeile = Spaltenüberschriften (sonst generische Namen `_c0`, `_c1`, ...).
- `inferSchema=True`: Spark liest die Datei einmal vorab und erkennt die Datentypen automatisch. Kostet etwas Zeit, vereinfacht aber alles Weitere.

Erkanntes Schema:

| Spalte      | Typ     | Wertebereich            |
|-------------|---------|-------------------------|
| `userId`    | integer | 1 – 162.541             |
| `movieId`   | integer | 1 – 209.171             |
| `rating`    | double  | 0,5 – 5,0 in 0,5er-Schritten |
| `timestamp` | integer | Sekunden seit Epoche    |

Eingelesene Zeilen: 100.836 (Small) bzw. 25.000.095 (25M) — passt zur GroupLens-Dokumentation.

## Schritt 2: Null-Werte entfernen

```python
df = df.dropna()
```

Verwirft Zeilen mit `null` in irgendeiner Spalte. Notwendig, weil:

- **ALS verträgt keine `null`-Werte** — würde zu Laufzeitfehler führen.
- Schützt vor Datenfehlern aus defekten Downloads oder zukünftigen Releases.

Empirisch entfernt: **0 Zeilen** auf beiden Datensätzen — MovieLens ist sauber. Der Schritt bleibt trotzdem im Code als Sicherheitsnetz.

## Schritt 3: Duplikate entfernen

```python
df = df.dropDuplicates(["userId", "movieId"])
```

Entfernt Mehrfachbewertungen desselben Nutzers für denselben Film. Schlüssel sind explizit `userId` + `movieId`, sodass unterschiedliche `rating`- oder `timestamp`-Werte für dasselbe Paar als Duplikat zählen.

**Warum nötig**: ALS modelliert jedes (Nutzer, Film)-Paar als einmalige Beobachtung. Duplikate würden bestimmte Bewertungen implizit übergewichten und das Modell verzerren [Koren et al. 2009].

Empirisch entfernt: **0 Zeilen** auf beiden Datensätzen.

## Schritt 4: Typen explizit casten

```python
df = (
    df.withColumn("userId",  col("userId").cast("int"))
      .withColumn("movieId", col("movieId").cast("int"))
      .withColumn("rating",  col("rating").cast("float"))
)
```

Drei Ziele:

1. **ALS-Schnittstelle**: ALS erwartet zwingend Integer-IDs. Schemainferenz hat sie zwar schon als `integer` erkannt — explizites Casten sichert es ab.
2. **Robustheit**: Edge-Cases (wissenschaftliche Notation, führende Nullen) könnten die Inferenz austricksen.
3. **Speicher**: `rating` von `double` (8 Byte) auf `float` (4 Byte) halbiert den Speicherbedarf dieser Spalte ohne Genauigkeitsverlust (die Skala hat nur 10 diskrete Werte). Bei 25M Zeilen: ~95 MB Ersparnis im RAM.

## Schritt 5: Train/Test-Split 80/20

```python
train, test = df.randomSplit([0.8, 0.2], seed=42)
```

| Split | Anteil | Zeilen (Small)  | Zeilen (25M)        |
|-------|--------|----------------:|--------------------:|
| Train | 80 %   | 80.578          | 19.998.878          |
| Test  | 20 %   | 20.258          | 5.001.217           |

**Warum 80/20**: Standard in der Empfehlungssystem-Literatur. Genug Trainingsdaten gegen Underfitting, genug Testdaten für stabilen RMSE. Bei 5M Test-Bewertungen ist die Aussagekraft mehr als ausreichend.

**Warum `seed=42`**: Macht den Split deterministisch reproduzierbar. Gleicher Code → gleicher Split → vergleichbare Modellergebnisse über mehrere Läufe.

**Warum Random-Split (statt zeitbasiert)**: Ein Time-Based-Split (alte Bewertungen → Train, neue → Test) wäre für ein produktives System realistischer. Für den Lehrkontext hier unnötig komplex; ungleichmäßige Verteilung der Zeitstempel würde zusätzliche Variabilität einbringen.

## Zusammenfassung

Die Pipeline besteht aus fünf einfachen, sequenziellen Schritten: Einlesen → dropna → dropDuplicates → cast → randomSplit. Auf beiden Datensätzen werden 0 Zeilen entfernt (MovieLens ist sauber), die Cleaning-Schritte bleiben trotzdem als Robustheits-Sicherung im Code. Der 80/20-Split mit fester Seed liefert reproduzierbare Trainings- und Testdaten für das ALS-Training in Kapitel 4.3. Die Pipeline ist identisch auf Mac (Small-Datensatz) und VM (25M-Datensatz) lauffähig — Unterschiede nur in Pfaden und Spark-Konfiguration.
