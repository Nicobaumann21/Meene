# 4.2 Datenvorverarbeitung

Die Rohdaten des MovieLens-Datensatzes liegen als CSV-Datei `ratings.csv` vor. Bevor sie dem ALS-Algorithmus von Spark MLlib übergeben werden können, sind mehrere Bereinigungsschritte erforderlich. Dieses Kapitel beschreibt die implementierte Pipeline (`src/pipeline.py`).

## 4.2.1 Einlesen und Schemaerkennung

Das Einlesen erfolgt über die Spark-DataFrame-API mit aktiviertem Header-Parsing und Schemainferenz:

```python
df_raw = (
    spark.read
        .option("header", True)
        .option("inferSchema", True)
        .csv(path)
)
```

Spark erkennt automatisch das Schema:

| Spalte    | Typ     | Bedeutung                           |
|-----------|---------|-------------------------------------|
| userId    | integer | Eindeutige Nutzer-ID                |
| movieId   | integer | Eindeutige Film-ID                  |
| rating    | double  | Bewertung (0.5–5.0 in 0.5-Schritten)|
| timestamp | integer | Unix-Zeitstempel der Bewertung      |

Im lokalen MovieLens-Small-Datensatz wurden **100.836 Bewertungen** eingelesen.

## 4.2.2 Bereinigungsschritte

Drei aufeinanderfolgende Transformationen stellen die Datenqualität sicher:

### Null-Werte entfernen
`df.dropna()` verwirft jede Zeile, die in mindestens einer Spalte `null` enthält. Dies schützt den Trainingslauf vor Laufzeitfehlern, da ALS keine fehlenden Werte verarbeiten kann.

### Duplikate entfernen
`df.dropDuplicates(["userId", "movieId"])` entfernt mehrfache Bewertungen desselben Nutzers für denselben Film. Solche Duplikate können die Matrixfaktorisierung verzerren, da das Modell jedes Paar (User, Film) als unabhängige Beobachtung behandelt.

### Typkonvertierung
ALS verlangt zwingend **Integer-IDs** für Nutzer und Filme sowie einen numerischen Bewertungstyp. Die explizite Konvertierung (`.cast("int")` bzw. `.cast("float")`) verhindert, dass die Schemainferenz von Spark in Edge-Cases (z. B. wissenschaftliche Notation in der CSV) abweichende Typen erzeugt.

```python
df.withColumn("userId",  col("userId").cast("int"))
  .withColumn("movieId", col("movieId").cast("int"))
  .withColumn("rating",  col("rating").cast("float"))
```

Im Small-Datensatz wurden nach der Bereinigung weiterhin **100.836 Zeilen** ausgewiesen — die Daten sind durchgängig konsistent. Auf dem 25M-Datensatz werden geringe Verluste durch Duplikate erwartet (siehe Kapitel 4.5).

## 4.2.3 Train/Test-Split

Für die spätere Evaluation des Modells wird der Datensatz vor dem Training in einen Trainings- und einen Testanteil aufgeteilt:

```python
train, test = df.randomSplit([0.8, 0.2], seed=42)
```

| Split | Anteil | Zeilenanzahl (Small) |
|-------|--------|----------------------|
| Train | 80 %   | 80.578               |
| Test  | 20 %   | 20.258               |

**Begründung der Aufteilung:**
- Das 80/20-Verhältnis ist Standard für Empfehlungssysteme und bietet einen Kompromiss zwischen ausreichend Trainingsdaten und einer aussagekräftigen Teststichprobe.
- Der feste `seed=42` macht die Aufteilung reproduzierbar — derselbe Code liefert auf demselben Datensatz stets dieselben Splits, was die Vergleichbarkeit der Modellläufe gewährleistet.

## 4.2.4 Zusammenfassung

| Schritt           | Methode                          | Zweck                              |
|-------------------|----------------------------------|------------------------------------|
| Einlesen          | `spark.read.csv(..., header)`    | DataFrame mit erkanntem Schema     |
| Nulls entfernen   | `dropna()`                       | ALS-Kompatibilität                 |
| Duplikate         | `dropDuplicates([uid, mid])`     | Verzerrung verhindern              |
| Typen casten      | `cast("int") / cast("float")`    | ALS-Anforderungen erfüllen         |
| Train/Test-Split  | `randomSplit([0.8, 0.2], seed)`  | Reproduzierbare Evaluation         |

Die bereinigten DataFrames `train` und `test` bilden die Eingabe für das ALS-Training (siehe Kapitel 4.3).
