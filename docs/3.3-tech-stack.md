## Anforderungen, aus denen sich der Stack ergibt

- Verarbeitung von Datenmengen, die größer sind als der verfügbare RAM (8 GB auf der VM gegenüber ~650 MB Rohdaten + Spark-Expansion)
- Vorhandene, ausgereifte ALS-Implementierung (keine Eigenentwicklung)
- Parallele Nutzung der 4 vCPUs ohne manuelle Thread-Verwaltung
- Reproduzierbare Versionspflege zwischen lokaler Umgebung und VM
- Etablierte Werkzeuge, für die ausreichend Doku und Lehrmaterial existiert

## Begründung der Kernkomponenten

### Apache Spark + MLlib

Spark ist das Standard-Framework für verteilte Datenverarbeitung und enthält mit MLlib eine produktionsreife Implementierung des **Alternating-Least-Squares-Algorithmus (ALS)** [Zhou et al. 2008; Meng et al. 2016]. ALS ist der etablierte Ansatz für Matrixfaktorisierung auf dünnbesetzten User-Item-Matrizen [Koren et al. 2009].

Konkrete Vorteile für dieses Projekt:

- **In-Memory mit Spill-to-Disk**: Wenn der RAM nicht reicht, lagert Spark automatisch auf Disk aus — wichtig bei 8 GB RAM.
- **DataFrame-API mit Catalyst Optimizer**: SQL-ähnliche Operationen werden automatisch optimiert (Predicate Pushdown, Column Pruning).
- **Automatische Parallelisierung**: Daten werden partitioniert und auf alle CPU-Kerne verteilt.
- **Single-Node-tauglich**: Spark läuft im *local-Mode* auch ohne Cluster, ideal für eine einzelne VM.

### PySpark

Spark ist in Scala geschrieben, bietet aber eine offizielle Python-API. PySpark wird gewählt, weil:

- Python im akademischen Data-Science-Umfeld dominiert,
- Jupyter-Notebook-Integration nativ funktioniert,
- die DataFrame-Semantik der von Pandas ähnelt (Wissens­transfer),
- Lehrmaterial (DataCamp, Coursera) PySpark als Standard verwendet.

Der Serialisierungs­overhead durch die Py4J-Brücke ist bei DataFrame-Operationen vernachlässigbar, weil diese im JVM-Bereich ausgeführt werden.

### Java 17

Spark 3.5 unterstützt offiziell Java 8, 11 und 17. **Java 17** wird gewählt, weil es:

- die aktuelle LTS-Version ist,
- über `brew` (Mac) und `apt` (Ubuntu) verfügbar und in beiden Umgebungen identisch,
- frei lizenziert ist (OpenJDK statt Oracle JDK).

### Python 3.11 (lokal) / 3.12 (VM)

Bewusst akzeptierte Differenz: PySpark 3.5.0 funktioniert mit beiden Versionen, der Pipeline-Code verwendet keine versionsabhängigen Sprach­merkmale. Die VM nutzt das Distributions-Python (3.12.3), um keine zusätzliche Komplexität durch `deadsnakes`-PPAs einzuführen. Bei Inkompatibilitäten kann jederzeit per `pyenv` auf 3.11 umgestellt werden.

### Pandas, Matplotlib, Jupyter

- **Pandas**: Konvertierung kleiner Spark-Ergebnisse für Ausgabe und Weiterverarbeitung (`toPandas()`).
- **Matplotlib**: De-facto Standard für statische Visualisierung in Python.
- **Jupyter**: Interaktives Arbeiten ohne wiederholten JVM-Start. Über SSH-Port-Forwarding bequem im lokalen Browser nutzbar (siehe Kapitel 4.1).

## Verworfene Alternativen

| Alternative                  | Warum verworfen                                                                  |
|------------------------------|----------------------------------------------------------------------------------|
| `scikit-learn` allein        | In-Memory-only, kein ALS, skaliert nicht auf 25M Zeilen mit 8 GB RAM            |
| `surprise`                   | Reine In-Memory-Bibliothek, bricht bei 25M auf der VM mit `MemoryError` ab      |
| TensorFlow Recommenders      | Overkill für klassisches CF; braucht GPU                                         |
| Dask                         | Weniger ausgereifte ML-Bibliothek, keine produktionsreife ALS-Implementierung   |
| Hadoop MapReduce             | Festplatten-zentriert, ~10× langsamer als Spark bei iterativen ML-Algorithmen    |

## Zusammenfassung

Der Stack besteht aus **Spark MLlib + PySpark + Java 17** als Kern, ergänzt um **Pandas, Matplotlib und Jupyter** für Auswertung und Exploration. Die Auswahl ergibt sich aus den Anforderungen: Datenmenge größer als RAM, vorhandene ALS-Implementierung, Parallelisierung auf 4 vCPUs, Reproduzierbarkeit. Alle Komponenten sind frei verfügbar und in beiden Umgebungen (Mac, Ubuntu-VM) installierbar.
