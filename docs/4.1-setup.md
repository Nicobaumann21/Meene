# 4.1 Setup der Entwicklungsumgebung

Dieses Kapitel dokumentiert die Einrichtung der **Ubuntu-VM** Schritt für Schritt. Die lokale Einrichtung auf macOS verläuft analog (Pakete via `brew` statt `apt`).

## Ziel-Hardware

| Eigenschaft     | Wert                                |
|-----------------|-------------------------------------|
| Hosting         | DHBW-Rechenzentrum                  |
| Betriebssystem  | Ubuntu 24.04 LTS                    |
| CPU             | 4 vCPUs                             |
| RAM             | 8 GB                                |
| Disk            | 50 – 100 GB                         |
| User            | `group6` mit `sudo`-Rechten         |
| Netzwerk        | Internet-Zugriff (apt, GroupLens)   |

Die 8 GB RAM sind für das 25M-Dataset knapp dimensioniert — die Spark-Konfiguration in Abschnitt „Spark-Konfiguration" trägt dem Rechnung.

## SSH-Zugriff und VSCode Remote-SSH

```bash
ssh group6@<vm-host>
```

Authentifizierung per öffentlichem Schlüssel in `~/.ssh/authorized_keys` (sicherer als Passwort, keine wiederholten Eingaben). Für die produktive Arbeit wird zusätzlich die **VSCode-Erweiterung „Remote-SSH"** genutzt: Editor läuft lokal, Code wird auf der VM ausgeführt.

## Schritt 1: System aktualisieren

```bash
sudo apt update && sudo apt upgrade -y
```

Bringt die Paketquellen und alle installierten Pakete auf den neuesten Stand. Auf einer frischen VM essenziell, um Konflikte zu vermeiden.

## Schritt 2: Systempakete installieren

```bash
sudo apt install -y openjdk-17-jdk python3-pip python3-venv git unzip wget
```

| Paket            | Zweck                                              |
|------------------|----------------------------------------------------|
| `openjdk-17-jdk` | Java 17 — Spark-Voraussetzung                      |
| `python3-pip`    | Python-Paketmanager                                |
| `python3-venv`   | Virtuelle Python-Umgebungen                        |
| `git`            | Repo clonen                                        |
| `unzip`, `wget`  | Datensatz herunterladen und entpacken              |

Verifikation:

```bash
java -version       # erwartet: openjdk version "17.x.x"
python3 --version   # erwartet: Python 3.12.x
git --version       # erwartet: git version 2.x.x
```

Konkret installierte Versionen: Java 17.0.19, Python 3.12.3, Git 2.43.0.

## Schritt 3: Virtuelle Python-Umgebung

```bash
python3 -m venv ~/venv
source ~/venv/bin/activate
pip install --upgrade pip
```

Die venv isoliert die Projekt-Pakete vom System-Python. **Wichtig**: `source ~/venv/bin/activate` muss in jeder neuen Shell wiederholt werden — am Prompt-Prefix `(venv)` erkennbar.

## Schritt 4: Python-Pakete installieren

```bash
pip install pyspark==3.5.0 pandas matplotlib jupyter
```

- PySpark-Version explizit gepinnt (`==3.5.0`) für Reproduzierbarkeit.
- Andere Pakete in jeweils aktueller Version (keine spezifischen Abhängigkeiten).
- Download ~380 MB, Installation ~2 Min.

Verifikation:

```bash
python3 -c "import pyspark; print('PySpark', pyspark.__version__)"
# erwartet: PySpark 3.5.0
```

## Schritt 5: MovieLens 25M herunterladen

```bash
mkdir -p ~/data
cd ~/data
wget https://files.grouplens.org/datasets/movielens/ml-25m.zip
unzip ml-25m.zip
ls -lh ml-25m/
```

Komprimiert ~250 MB, entpackt ~1,1 GB. Inhalt: siehe Kapitel 2.4. Daten liegen **außerhalb** des Projektordners (`~/data/ml-25m/`), damit sie nicht in die Versionskontrolle geraten.

## Schritt 6: Repository clonen

```bash
cd ~
git clone https://github.com/Nicobaumann21/Meene.git movie-recommender
cd movie-recommender
```

Da das Repo privat ist: Beim Clone wird nach Login gefragt.
- **Username**: GitHub-Username (`Nicobaumann21`)
- **Passwort**: Personal Access Token (PAT), generiert unter https://github.com/settings/tokens (Scope: `repo`)

Damit der Token nicht bei jedem `git pull` neu eingegeben werden muss:

```bash
git config --global credential.helper store
```

Speichert den Token in `~/.git-credentials` im Klartext. Für eine private Studien-VM ok; in Produktion wäre ein SSH-Key vorzuziehen.

## Spark-Konfiguration für die VM

Wegen der knappen 8 GB RAM müssen die Spark-Parameter gezielt gesetzt werden:

| Parameter                       | Wert | Begründung                                                        |
|---------------------------------|------|-------------------------------------------------------------------|
| `spark.driver.memory`           | 6g   | Lässt 2 GB für OS und Hilfsprozesse                               |
| `spark.driver.maxResultSize`    | 2g   | Zwischen­ergebnisse bei 25M-Aggregaten überschreiten den 1g-Default |
| `spark.sql.shuffle.partitions`  | 100  | Gutes Verhältnis von Parallelität zu Overhead bei 4 vCPUs         |

Die Werte werden als CLI-Argumente an `src/pipeline.py` übergeben (siehe Kapitel 4.5) — Code und Konfiguration bleiben getrennt.

## Schritt 7: Jupyter mit SSH-Port-Forwarding

**Auf der VM:**

```bash
source ~/venv/bin/activate
cd ~/movie-recommender
jupyter notebook --no-browser --port=8888
```

Jupyter gibt eine URL mit Token aus, z. B. `http://localhost:8888/?token=abc123...`.

**Auf dem Mac (neues Terminal):**

```bash
ssh -L 8888:localhost:8888 group6@<vm-host>
```

Leitet Port 8888 von der VM auf den lokalen Port 8888 um. Anschließend die URL aus dem Jupyter-Output im lokalen Browser öffnen. Vorteil: Notebook-Server bleibt auf der VM nicht öffentlich, ist aber lokal bedienbar.

## Schritt 8: Verifikation des Gesamt-Setups

End-to-End-Test mit dem 25M-Datensatz:

```bash
source ~/venv/bin/activate
cd ~/movie-recommender
python src/pipeline.py \
    --ratings ~/data/ml-25m/ratings.csv \
    --driver-memory 6g \
    --max-result-size 2g \
    --shuffle-partitions 100
```

Erwartete Ausgabe:
- `Zeilen (roh): 25.000.095`
- `Zeilen (bereinigt): 25.000.095` (0 entfernt)
- `Train: 19.998.878` / `Test: 5.001.217`
- Gesamtlaufzeit ca. 80–110 s (gemessen: 95,4 s — siehe Kapitel 4.5)

Wenn diese Zahlen erscheinen, ist die VM vollständig einsatzbereit.

## Zusammenfassung

Die VM-Einrichtung umfasst acht Schritte: System aktualisieren → Pakete installieren → venv anlegen → PySpark installieren → Datensatz herunterladen → Repo clonen → Spark konfigurieren → Jupyter starten. Jeder Schritt hat einen klaren Verifikations­punkt. Die Spark-Konfiguration ist auf die 8-GB-RAM-Begrenzung der VM zugeschnitten. Das Setup ist vollständig reproduzierbar — alle Befehle sind oben dokumentiert.
